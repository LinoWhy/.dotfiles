# Module Review

对指定模块执行完整代码评审，并按照下方内置模板写出 Markdown 报告。

## Inputs

从用户输入中解析：

- 模块名称
- 仓库路径或代码路径
- 需求或设计文档路径，可选；未提供时视为“无”
- 输出文件名，可选；未提供时使用 `<module>_code_review.md`

## Review Workflow

1. 基于输入路径检索目标模块实现，对照需求与设计文档理解功能目标。
2. 严格依据内置模板逐项分析模块。
3. 逐条填写检查项表格：
   - 未涉及的项写“未涉及”。
   - 通过的项只写“通过”，不附加说明。
   - 有问题的项写具体问题描述，并引用问题编号，例如“见问题 P1-1”。
4. 必要时引用文件路径、函数名或关键代码作为证据。
5. 在“详细问题说明”中按严重程度归类至 `P0`、`P1`、`P2`、`P3`，只列出实际发现的问题。
6. 在“总结”中按优先级列出所有问题的简要清单；若某级别无问题则写“无”。
7. 将完整评审结果写入输出文件。

## Output Rules

- 严格使用内置模板，不新增、删除、合并、拆分或调整章节顺序。
- 不修改检查项的顺序和内容。
- 表格“结果”列只允许填写“通过”、“未涉及”或带问题编号的具体问题描述。
- 有问题的检查项必须在“详细问题说明”中展开。
- 引用代码或路径时使用 Markdown 行内代码标记。
- 不使用 emoji，不添加模板以外的说明。
